# djradu — Rust Trading Telemetry

> **Repo:** `radubadila14-cyber/djradu`  
> **Related local project:** `radu-trading-system` (see [Separation note](#separation-local-vs-repo))

A Rust workspace implementing a **CME-style trading telemetry contract** —
typed events, JSONL writer, golden-trace simulator, KPI viewer, and an
optional integration shim for larger trading apps.

---

## Project Separation: local vs repo

| | Local: `radu-trading-system` | GitHub: `djradu` |
|---|---|---|
| **Purpose** | Full trading app (Postgres, Redis, Quant API) | Telemetry contract + tooling |
| **Lives in** | `%USERPROFILE%\Documents\radu-trading-system` | This repo |
| **Runtime deps** | Railway (Postgres + Redis), env vars | None (offline, no external services) |
| **CI** | Not in CI | `cargo fmt / clippy / test` via GitHub Actions |

The two projects are **intentionally separate**.  `djradu` publishes
`telemetry-core` as a library crate.  `radu-trading-system` adds it as a
dependency (see [Integrating telemetry-core](#integrating-telemetry-core)).

## Quick Start

```bash
# Check everything compiles (no external services needed)
cargo check --workspace

# Run the golden trace generator
cargo run -p telemetry-sim
# → writes telemetry/golden_trace.jsonl

# Compute KPIs from the trace
cargo run -p telemetry-viewer
# → prints slippage, latency, fill stats

# Run all tests
cargo test --workspace

# CI checks (must all pass)
cargo fmt --check
cargo clippy --workspace -- -D warnings
cargo test --workspace
```

## Integrating telemetry-core

To embed telemetry-core into a larger Rust trading application:

### Step 1 — Add as a path or git dependency

**Path dependency** (for a monorepo / local workspace):
```toml
# your-trading-app/Cargo.toml
[dependencies]
telemetry-core = { path = "../djradu/crates/telemetry-core" }
```

**Git dependency** (for a standalone project):
```toml
[dependencies]
telemetry-core = { git = "https://github.com/radubadila14-cyber/djradu" }
```

### Step 2 — Enable optionally behind a feature flag (recommended)

Keep the dependency optional so the app compiles without it when telemetry
is not needed (e.g. during unit tests or on constrained environments):

```toml
[dependencies]
telemetry-core = { path = "../djradu/crates/telemetry-core", optional = true }

[features]
telemetry-integration = ["dep:telemetry-core"]
```

### Step 3 — Wire into application boundaries

This repo ships a ready-made integration shim in `src/telemetry.rs`,
compiled only when `--features telemetry-integration` is passed:

```bash
cargo build --features telemetry-integration
cargo test  --features telemetry-integration
```

Minimal wiring example:

```rust
// main.rs (inside `#[cfg(feature = "telemetry-integration")]` block)
use crate::telemetry::TelemetrySession;

// 1. Startup boundary
let t0 = std::time::Instant::now();
let mut telem = TelemetrySession::open("telemetry/live_trace.jsonl")?;

// 2. DB boundary
let pg_pool = db::connect_postgres(&cfg.database_url).await?;
telem.emit_boundary_latency("db.connect", t0.elapsed().as_micros() as u64);

// 3. Cache boundary
let mut redis = cache::connect_redis(&cfg.redis_url).await?;
telem.emit_boundary_latency("cache.connect", t0.elapsed().as_micros() as u64);

// 4. Startup complete
telem.emit_startup(t0.elapsed().as_micros() as u64);
```

The session emits **`system.latency`** events to a JSONL file.
Run `cargo run -p telemetry-viewer -- telemetry/live_trace.jsonl` afterwards
to compute latency stats.

## CME Telemetry Contract

See [`telemetry/spec.md`](telemetry/spec.md) for the full specification:

- Event naming convention (FIX-style)
- Required causality IDs (`trace_id → decision_id → cl_ord_id → exec_id`)
- Multi-timestamp model (`ts_exchange`, `ts_local_rx`, `ts_decision`, …)
- FIX field mapping (tag 54 / 40 / 59 / 31 / 32 / 14 / 151 / …)
- **Maker/taker inference** (from `AggressorIndicator` tag 1057 or heuristics)
- KPI formulas (slippage, adverse selection, latency, fill ratio)
- Immutable log rules and schema versioning

## Architecture (radu-trading-system)

```
Rust Backend
├── PostgreSQL (Railway) — trades, market data, model configs
├── Redis (Railway)      — caching, real-time data
├── Quant APIs           — quantitative trading strategies
└── Lambda Labs          — GPU model training (Phase 3)
```

### Setup

1. Copy environment template:
   ```bash
   cp .env.example .env
   ```

2. Fill in Railway credentials in `.env`:
   - PostgreSQL plugin → Connect → copy `DATABASE_URL`
   - Redis plugin → Connect → copy `REDIS_URL`

3. Run:
   ```bash
   cargo run
   ```
